# shadcn/ui guide (castor-kit)

castor-kit's frontend is built on **shadcn/ui (new-york, Radix) + Tailwind CSS v4 + motion + lucide-react**; the language is JavaScript (JSX), and UI copy is written in Chinese (as the i18n key).
Design system: `docs/frontend-design-system.md`; project conventions: `AGENTS.md` "Frontend conventions".

## Workflow

1. **Read the reference implementation before writing code**:
   - Standard CRUD list page: `apps/web/src/modules/admin/pages/users/index.jsx`
   - Cards / charts / motion: `apps/web/src/modules/admin/pages/dashboard/index.jsx`
   - Form page: `apps/web/src/modules/admin/pages/profile/index.jsx`
   - Templates: `docs/templates/frontend/list_page/index.jsx`, `docs/templates/frontend/detail_page/index.jsx`
   - Pages generated by `pnpm scaffold` are instances of the list page pattern (field type → form component mapping in PATTERNS.md)
2. **Reuse first**: `@/shared/components/*` (PageHeader / DataTable / FilterBar / FormDialog / FormFields / ConfirmAction / StatusBadge / ImportDialog / ExportDialog ...); compose `@/components/ui/*` directly only when something is missing.
3. **Check the docs**: the official docs are authoritative for the shadcn component API (https://ui.shadcn.com/docs/components ; prefer the shadcn MCP for querying the registry when available); when they conflict with the implementation in the repo's `apps/web/src/components/ui/`, the repo wins (it has been adjusted to this project's tokens; for example, Button has an extra `variant="brand"`).
4. **Need a new primitive**: use the relay script (the shadcn CLI on this machine fails to reach ui.shadcn.com directly):

   ```bash
   apps/web/scripts/shadcn-add.sh hover-card        # add
   apps/web/scripts/shadcn-add.sh --view badge      # only view the registry source
   apps/web/scripts/shadcn-add.sh badge -o -y       # overwrite existing files (loses local changes, such as button's brand variant; confirm first)
   ```

   The script starts a local Node relay (curl fetches https://ui.shadcn.com/r/... through the system proxy), clears `HTTP(S)_PROXY`, runs `REGISTRY_URL=http://127.0.0.1:<port>/r npx shadcn@latest add ...`,
   and shuts the relay down when done; it also rewrites `import { cn } from "cn"` in the registry source back to `@/lib/utils` and removes the wrongly installed `cn` package. After adding, check dependency changes with `git diff apps/web/package.json`, and change the component's colors to semantic classes.
5. **Self-check**: `cd apps/web && npx eslint <file>` with zero errors; `npx vite build` passes; check both light and dark themes and widths <768px; `pnpm verify -- --module <name>` passes.

## Don'ts

- ❌ Other UI component libraries (antd, MUI, etc.): use only `@/components/ui/*`, `@/shared/components/*`, lucide-react and Tailwind semantic color classes
- ❌ Hard-coded hex colors in pages (exceptions: shading inside canvas / three.js / WebGL, chart data colors; for charts, use `useChartColors` first)
- ❌ Large inline styles for layout (use Tailwind classes; only dynamic values may use style)
- ❌ Emoji as icons (use lucide-react)
- ❌ Each page building its own tables / dialogs / confirmations / import-export (reuse the shared components)
- ❌ More than one `variant="brand"` primary button on a page (use outline / ghost for the rest); purple; large gradient areas (gradients are only accents)
- ❌ Flashy, meaningless animations; ignoring `prefers-reduced-motion`
- ❌ Calling `setState` synchronously inside `useEffect` (eslint's react-hooks/set-state-in-effect reports it; use a promise callback or `useCrudList`)
- ❌ Calling `fetch` directly (all requests go through `@/shared/api/request`, and responses are already unwrapped: `res.items`, not `res.data.items`)
